==== 啟動器群組圖表增強

「管理用戶端存取」頁面上用於顯示區塊裝置啟動器群組的圖表現在包含更多主機詳細資訊。將滑鼠懸停在圖表中的主機上時，將顯示主機詳細資訊，包括主機名稱、執行個體 ID、工作負載類型、區域和 iSCSI 限定名稱（IQN）。



==== 針對架構完善的問題進行電子郵件增強

新的電子郵件設計針對 Workload Factory 偵測到的組態問題，提供更多詳細資料與背景資訊。電子郵件包含已分析的資源數量、有多少資源發生警告或關鍵問題，以及這些問題是什麼。電子郵件也會連結至 FSx for ONTAP 完善架構儀表板，讓您可以立即解決問題。



==== 精心設計的儀表板增強功能



===== 支援選定的組態檢查

您可以手動對選定的組態執行分析，以便只分析您感興趣的組態，從而減少等待時間。



===== 架構良好的分析中的新建議

Workload Factory 現在在針對 FSx for ONTAP 檔案系統的完善架構分析中加入了以下配置：

對於儲存設備工作負載：

* *將主機連線至容錯移轉節點*：檢查主機是否已連線至主動被動式 FSx for ONTAP 檔案系統中的容錯移轉節點，以確保可靠性。
* *將主機連接至首選節點*：檢查主機是否使用首選節點連接至其區塊裝置，以提升效能與效率。
* *ARP/AI 多裝置偵測漏洞*：當一個 Volume 僅連接一個區塊裝置時，ARP/AI 可提供全面的保護。如果一個 Volume 連接了多個區塊裝置，Workload Factory 會將這些區塊裝置移至新的 Volume，以確保每個 Volume 僅連接一個區塊裝置。
* *複製清理*：檢查是否有超過 30 天的 Volume 複製可以刪除，以最佳化儲存設備使用並降低成本。
* *將 igroup 作業系統與主機配對*：檢查啟動器群組（igroup）的作業系統是否與主機的作業系統相符，以防止 I/O 或效能問題。


對於 Kubernetes 工作負載：

* *QoS 組態*：檢查 Kubernetes 持久性 Volume 是否受到 ONTAP QoS 原則的保護，以確保效能與效率。
* *專用 Kubernetes 儲存設備 VM*：檢查檔案系統是否使用專用儲存設備 VM 來處理 Kubernetes 工作負載，以提高隔離並簡化儲存管理。
* *專用 Kubernetes 匯出原則*：檢查每個 Kubernetes 持久性 Volume 是否具有專用的匯出原則，該原則僅允許從叢集的工作節點進行存取。
* *Kubernetes iSCSI 後端的雙向 CHAP*：檢查 Trident iSCSI 後端是否已啟用相互 CHAP 驗證以確保安全性。
* *在應用程式儲存設備 VM 上停用 `showmount`*：檢查在應用程式儲存設備 VM 上是否已停用 `showmount`，以防止用戶端列出其無法存取的匯出。


對於資料庫工作負載：

* *SAP HANA 快照原則*：檢查 SAP HANA Volume 的快照原則是否設定為「無」，以降低儲存設備成本並提高作用中資料庫資料的效能。
* *MySQL 快照原則*：檢查 MySQL Volume 的快照原則是否設定為「無」，以降低儲存設備成本並提高作用中資料庫資料的效能。
* *PostgreSQL 快照原則*：檢查 PostgreSQL Volume 的快照原則是否設定為「None」，以降低儲存設備成本並提高作用中資料庫資料的效能。




===== 組態的目前和建議值

您可以在設計完善的儀表板中檢視某些未最佳化組態的目前值和建議值。這可讓您在修復之前了解建議值為何。

* 冷資料分層
* Snapshot 原則
* SSD 容量餘裕




==== 成本改進



===== 成本預測與洞察

現在，您可以使用成本預測功能來預測 FSx for ONTAP 檔案系統的成本。這有助於您有效地規劃預算並最佳化資源。您也可以檢視有關成本和使用模式的深入分析，以找出成本最佳化的機會。



===== AWS 成本和使用情況報告（CUR）

Workload Factory 現在使用 AWS 成本和使用情況報告（CUR）而非 AWS Cost Explorer 來提供詳細的帳單記錄，並將這些記錄傳送到客戶擁有的 S3 儲存桶。CUR 提供更佳的成本精細度，並為進階 FinOps、退款和成本分配使用案例奠定基礎。



==== 儲存虛擬機器移轉改進

Workload Factory 在使用者介面中提供了增強的儲存設備虛擬機器移轉指導。這包括逐步說明和在將移轉提交到生產環境之前進行的測試執行。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-replication.html["了解更多關於儲存設備 VM 移轉"]



==== 複寫延遲電子郵件通知改善

當發生大量相關的複寫延遲事件時，Workload Factory 會自動將它們合併到單一電子郵件通知中，這樣您就不會被通知淹沒。



==== 自動容量管理增強

現在您可以啟用自動容量管理通知功能，以便在要求 Workload Factory 自動管理容量之前先體驗該功能。當您的檔案系統容量不足時，您將收到通知。



==== 處理量決策點

現在您可以查看用戶端處理量建議和自動化決策點。將游標停留在決策點上即可檢視詳細資訊，例如目前和建議的 SKU 或時間範圍內的超標計量（%）。



==== 客戶管理的 Bedrock 分類支援

Workload Factory 現在允許您使用自己的 Amazon Bedrock 設定進行工作負載標籤分類。您可以提供自己的 Bedrock 端點和憑證，以便分類請求透過您自己的 Bedrock 組態執行。

精心設計的儀表板現在包含資料庫配置建議，方便您根據最佳實踐評估和優化您的設定。儀表板中包含的首批配置如下：

==== EVS TCO 計算器支援 i7i.metal-24xl 和 i7i.metal-48xl 執行個體

EVS TCO 計算器現在支援將 AWS i7i.metal-24xl 和 i7i.metal-48xl EC2 執行個體作為叢集主機。與 i4i.metal 配置相比，i7i.metal-24xl 執行個體可將 EVS 的運算初始成本降低約 33%，vSAN 儲存設備初始成本降低約 25%。

==== 檢查並重新整理自訂儀表板資料

現在您可以查看自訂儀表板計量的最後更新時間，並手動重新整理它們。將滑鼠停留在 *重新整理資料* 上即可檢視最後更新的日期和時間。

選擇 *重新整理資料* 來開始新的掃描。橫幅會確認掃描已開始，且按鈕在掃描完成前將處於停用狀態。

*重新整理資料* 和 *立即載入* 都會在 Tracker 中建立資料收集事件。

如果您的要求中未包含某些區域，自訂儀表板現在會要求您選擇一個或多個區域。儀表板資料僅限於您選擇的區域。

link:https://docs.netapp.com/us-en/workload-setup-admin/create-custom-dashboard.html["了解如何建立自訂儀表板"]



==== 建立連結的 IAM 原則

用於建立連結的 CloudFormation 範本和 Terraform 程式碼現在使用 IAM 原則，而不是即時 Lambda 權限。

link:https://docs.netapp.com/us-en/workload-setup-admin/create-link.html["學習如何建立連結"]

現在您可以使用 Tracker 審查 AI 代理程式設定的變更，並且在讀寫模式下，審查每個核准要求，包括代理程式的問題和使用者的答案。

透過 Workload Factory API 進行的資源變更由執行該操作的 Workload Factory 服務記錄。

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-agent.html#audit-and-tracking-for-agent-actions["了解代理程式操作的稽核和追蹤"]

Workload Factory 已更新用於建立連結的 Codebox 輸出，將即時 Lambda 權限替換為 CloudFormation 範本與 Terraform 的 IAM 原則。

==== 自訂儀表板更新

自訂儀表板現在讓您更輕鬆地管理工作。

您可以直接從目錄編輯儀表板，包括計量、圖表和時間範圍。

編輯儀表板時，Workload Factory 會重新開啟聊天，並顯示您先前的提示和訊息。接著您可以更新儀表板、儲存變更或還原先前的版本。

只有儀表板建立者才能編輯儀表板。在您編輯時，其他使用者無法看到您的變更，直到您儲存為止。

儀表板目錄現在包含更多篩選器，可協助您根據類別和狀態快速找到儀表板。

如果您的系統管理員停用了 AI 功能或您的每月信用額度已達到上限，則儀表板的建立和編輯功能將被停用。

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-custom-dashboards.html["了解自訂儀表板"]

link:https://docs.netapp.com/us-en/workload-setup-admin/create-custom-dashboard.html["建立自訂儀表板"]

==== 擴充 AWS 服務的工作負載標記探索

Workload Factory 現在可以偵測更多 AWS 服務以進行工作負載標記，擴充對可標記資源的支援。現在它可以找到 Amazon EKS 和 Amazon WorkSpaces 資源，並將它們納入標記系統中，以便進行標記。



==== 成本儀表板增強功能

成本儀表板現在包含成本高階主管總結區塊，提供貴組織支出的總覽，協助您快速了解與管理成本。Workload Factory 的 AI 助理 Ask Me 可根據您的成本資料提供額外的深入見解與建議。您可以與 Ask Me 互動，以取得最佳化成本的詳細說明與建議。

此外，您還可以按一個或多個檔案系統以及檔案系統中的一個或多個 Volume 篩選成本資料。套用篩選器後，Workload Factory 將顯示：

* 每月預計總成本
* 每 GiB/月預計成本
* 按服務的詳細成本明細


除了檔案系統和 Volume 級成本分配之外，所有成本資訊直接來自 AWS Cost Explorer API；Workload Factory 會估算檔案系統和 Volume 級成本分配。



==== 架構良好的儀表板存取

您可以從 Workload Factory 主控台的主選單以及檔案系統內部存取架構完善的儀表板。若要從主選單找到架構完善的儀表板，請選擇主選單，然後選擇 *架構完善*。

image:well-architected-menu-option.png["Workload Factory 控制台中設計良好的選單選項"]



==== 架構良好的分析中的新建議

Workload Factory 現在在針對 FSx for ONTAP 檔案系統的完善架構分析中加入了以下配置：

* *Volume 空間管理組態*：建議為 FSx for ONTAP Volume 啟用協調的 Volume 空間管理。
* *FSx 與 AWS MGN 整合*：建議將所需的 AWS MGN 就緒組態應用於選定的 FSx for ONTAP 檔案系統。


link:https://docs.netapp.com/us-en/workload-fsx-ontap/configuration-analysis.html["了解更多關於您的 FSx for ONTAP 檔案系統的最佳實務做法建議。"]



==== Volume 資源管理器增強功能

Volume 資源管理器是 Workload Factory 主控台的集中位置，您可以在此檢視和管理跨不同檔案系統的所有 Volume。它提供有關每個 Volume 的詳細資訊，包括其效能、使用情況和保護狀態。此版本的增強功能包括工作負載選擇、Volume 延遲顯示以及 Volume 的 ARP/AI 狀態。



===== Volume 總管支援工作負載選擇

Workload Factory 會根據 Volume 的特性及其使用模式預設選擇工作負載。現在，您可以從 Volumes explorer 變更一個或多個 Volume 的工作負載。



===== Volume 資源管理器顯示 Volume 延遲

Volume 資源管理器會顯示 Volume 延遲狀態，包括以下幾種狀態：未設定、在臨界值內和超出臨界值。這些狀態有助於您尋找並修復 Volume 層級的效能瓶頸。



===== Volume 總管顯示所有檔案系統中 Volume 的 ARP/AI 狀態

Volume 資源管理器畫面現在包含一張卡片，顯示所有檔案系統中 Volume 的 NetApp 具備 AI 的自主勒索軟體保護（ARP/AI）狀態。卡片會顯示受保護 Volume 的數量，並指出是否有任何 Volume 處於風險之中。透過該卡片，您可以*分析攻擊*，以調查潛力的勒索軟體威脅，並採取適當行動來安全的您的資料。

image:volumes-explorer-arp-ai-card.png["螢幕截圖顯示「Volume 資源管理器」畫面上新增了一張卡片，顯示所有檔案系統中 Volume 的 ARP/AI 狀態。該卡片指出受保護 Volume 的數量以及任何存在風險的 Volume。使用者可以選擇「分析攻擊」文字來調查可疑攻擊，並採取適當措施以確保其資料安全的。"]

link:https://docs.netapp.com/us-en/workload-fsx-ontap/ransomware-protection.html["深入瞭解勒索軟體保護。"]



==== 不健康複寫關係的電子郵件通知
