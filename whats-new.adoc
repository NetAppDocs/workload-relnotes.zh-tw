=== 設定與管理



==== 更新了資料庫的 IAM 權限原則。

資料庫的權限已更新，以改善功能存取並限制不必要的 SSM 存取。

檢視、規劃和分析權限僅限於 AWS SSM 文件。擁有這些權限，您可以檢視主機、執行個體和資料庫。您也可以對資源執行基本的隨需架構完善分析。

操作和修復權限可讓您變更資源、分析錯誤日誌、取得資源的全面架構完善分析並修復組態問題。

link:https://docs.netapp.com/us-en/workload-setup-admin/permissions-reference.html["權限參考"]



==== 自訂儀錶板



===== 自訂儀表板的通知

Workload Factory 現在會在您的自訂儀表板準備就緒或建立失敗時通知您。

建立自訂儀表板後，您將收到一則通知，其中包含可直接檢視該儀表板的連結。如果建立失敗，您將收到一則通知，其中包含指向自訂儀表板清單的連結，以便重試。

這可以幫助您了解儀表板何時準備就緒，並方便您審查或重新建立它。

link:https://docs.netapp.com/us-en/workload-setup-admin/create-custom-dashboard.html["學習如何建立自訂儀表板"]

link:https://docs.netapp.com/us-en/workload-setup-admin/configure-notifications.html["了解如何設定通知"]



===== 私有和公用自訂儀表板

自訂儀表板現在包含共享設定。您可以將儀表板設為私人，也可以與團隊成員共享。

預設情況下，新建的儀表板是私有的，只有您自己可見。您可以隨時將儀表板設為公開，與 Workload Factory 帳戶中的所有人共享。

每個儀表板卡片都會顯示「私人」或「公有」標籤，以便您快速查看哪些儀表板是共享的。

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-custom-dashboards.html#view-and-share-dashboards["了解儀表板的可見度和共享功能"]

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-custom-dashboards.html#change-dashboard-visibility["了解如何共享儀表板"]



==== AI 功能管理

您可以透過 Workload Factory 管理中的以下設定來控制整個組織對 AI 功能的存取。

* 使用 NetApp 代管的 Bedrock（建議使用，預設啟用，設有每月點數限制）
* 關閉所有人工智慧功能


新的管理頁面讓您可以集中管理這些設定。

AI 功能包括「問我」、自訂儀表板、規則建構者以及 EMS、資料庫日誌和 Volume 延遲分析器。

如果 AI 功能已關閉，使用者將會看到一則訊息，提示 AI 無法使用。

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["了解如何管理人工智慧功能"]



[[eda-workloads]]
=== EDA 工作負載



==== AI 延遲分析及成本控制

身為 Workload Factory 系統管理員，您可以控制整個組織對 AI 延遲分析的存取。

* *NetApp 代管 AI 額度*：如果您的系統管理員啟用此功能，您可以透過 NetApp 的代管 Amazon Bedrock 整合使用 AI 分析。無需額外設定。您的每月使用量受分配的預算限制。如果您達到每月限額，AI 功能將停用，您將會看到一則訊息。
* *系統管理員已停用*：如果您的系統管理員關閉了 AI 功能，則 AI 分析選項將呈灰色顯示，並且您會看到一則訊息，提示該功能已關閉。




==== 彈性處理量增加管理

現在，您可以從 EDA 概述頁面管理一個或多個選定的 FSx for ONTAP 檔案系統的處理量增加行為。

* *模式選擇*：選擇 *Automate* 或 *Recommend*。
* *批次更新*：選擇一個或多個檔案系統，並在單一行動中套用模式和參數變更。
* *變更處理量管理對話方塊*：在對話方塊中使用 EDA 預設值編輯處理量增加設定。
* *進階設定*：在可展開的*進階組態*區段中設定其他處理量決策參數。
* *表格可見度*：叢集表中新增了 *處理量管理* 欄，可透過欄設定啟用。
* *上位卡組態*：上位卡現在支援處理量提升模式組態，類似 SSD 管理。


link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html["了解如何使用概覽儀表板"^]。

=== Amazon FSX for NetApp ONTAP 產品



==== 適用於所有 FSx for ONTAP 系統的全新架構完善儀表板現已推出

現在，您可以透過 NetApp Workload Factory 中全新的架構完善儀表板，對 FSx for ONTAP 檔案系統進行架構完善分析。新儀表板集中展示了您所有帳戶和區域中的檔案系統及其配置。當您從檔案系統存取「架構完善」索引標籤時，會出現彈出通知。您可以透過在 Workload Factory 左側導覽功能表中選擇「架構完善」來存取新儀表板。

您仍然可以存取特定檔案系統的架構完善分析，以及從 Storage 中的 *Well-architected* 功能表選項進行存取。



==== 儲存儀表板新增了小工具

儲存設備儀表板現在包含兩個新的小工具，可協助您了解如何使用儲存設備，以及找到最佳化儲存設備的方法。

* *熱門探索到的工作負載* 顯示標記服務在您的環境中發現的工作負載資料。檢視信賴度評分高於 80% 且包含相關 FSx 資源（例如 Volume 和區塊裝置）的工作負載。每個工作負載都會顯示其名稱、資源數量、已配置容量和已使用容量。依資源數量（預設）、已配置容量或已使用容量排序，以快速識別最大的工作負載並了解儲存設備使用模式。
* *AI 驅動的洞察與觀察* 展示 AI 產生的關於您代管資產的洞察。該元件會審查您所選範圍內的資產資料，並突出顯示關鍵領域的前三項重要發現，包括容量、效能、資料保護、複寫、成本節約效益和儲存設備趨勢。


每個洞察都包含總結、詳細調查結果和建議措施。展開洞察即可查看更多詳情，並根據問題的嚴重性、效能改進和成本節約效益機會來確定優先順序。



==== 工作負載標記



===== AWS Systems Manager 整合工作負載標記

工作負載標記服務現已與 AWS Systems Manager 協同運作，為主機清單資料新增更多詳細資訊。Workload Factory 現在可以收集和處理 SSM 清單資訊，以便更好地識別和分類工作負載。AWS SSM 屬性也包含在標記程序中，以提高工作負載探索的準確性。

在架構完善的儀表板中，每個與 Volume 相關的組態現在都在資源表中包含「工作負載」欄位。此欄位顯示 Workload Factory 與每個 Volume 關聯的工作負載。



==== 工作負載標記和 AI 功能

當系統管理員停用 AI 功能時，工作負載將不會被標記。如果在 Workload Factory 帳戶設定中關閉了 AI 功能，標記服務將無法識別或分類儲存資源上的工作負載。

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["了解人工智慧管理"^]。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/explore-savings.html["探索 Amazon Elastic Block Store、FSx for Windows File Server 和 Elastic File System 為您的儲存設備環境節省成本。"]



===== 將複製延遲資料匯出至 CSV

建立與您的工作負載和優先順序相符的 AI 驅動儀表板，以便輕鬆了解營運狀況。自訂儀表板讓您擺脫固定檢視的束縛，專注於最重要的資訊。

[[eda-workloads]]
=== EDA 工作負載



==== 增強延遲分析，同步顯示延遲、IOPS 和處理量圖表

延遲分析面板現在包含一個「詳細延遲分析」頁面，其中包含同步的效能圖表：

* *延遲圖*：顯示延遲隨時間的變化情況，並帶有閾值線，當超過限制時會發出警示。
* *IOPS 圖表*：顯示每秒作業數，並附有閾值線和過去超出限制的指示器。
* *處理量圖*：顯示資料傳輸速率（DataReadBytes 或 DataWriteBytes）。在篩選器中選取 Metadata 時，處理量圖不會顯示任何資料。


所有圖表均使用相同時間線，並根據事件是讀取還是寫入自動顯示正確的指標。

您可以調整檢視，並將延遲峰值與 IOPS 和處理量的變化關聯起來。違規標記和懸停細節可協助您查看何時超過臨界值，並審查偵測到的違規行為的關鍵計量。

https://docs.netapp.com/us-en/workload-eda/task-analyze-latency-trends.html["學習如何使用多個圖表分析延遲趨勢"^].



==== 設定延遲通知頻率

現在您可以選擇接收延遲違規電子郵件通知的頻率：

* *每天提醒我（建議）*：當任何 FSx for ONTAP 檔案系統出現新問題時，您將收到通知。


如果一天內同一檔案系統上發生多個延遲問題，您只會收到一封電子郵件。

Workload Factory 在向檔案系統發出延遲警報後，會等待 24 小時，再向該檔案系統發出另一個警報。

* *Notify on any latency breach (every 20 minutes)*：偵測到違規情況時，最多每 20 分鐘收到一次通知。


預設啟用每日通知，以減少電子郵件數量，同時仍能提醒您注意延遲問題。您可以在設定延遲監控或編輯閾值設定時變更通知偏好設定。

https://docs.netapp.com/us-en/workload-eda/task-configure-latency-monitoring.html["了解如何設定延遲監控"^].
